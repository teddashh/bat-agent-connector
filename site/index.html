Let one agent watch the others.

派一個 agent 盯場就好。

It speaks BAT's own remote protocol, so Claude Code, Codex, Cursor, Hermes, or a shell script can see which sessions are done, blocked on a question, or out of quota. Nothing writes until you enable it per host.

它直接走 BAT 自己的遠端協定，讓 Claude Code、Codex、Cursor、Hermes 或一支 shell 腳本，都看得出哪些 session 做完了、卡在問題上，或是額度用完了。在你逐台主機開啟之前，它不會寫入任何東西。

The problem問題在哪裡

Several agents, several tabs, nobody watching.

開了一堆 agent，卻沒人在看。

Long-running coding agents finish, stall on a question, hit a usage quota, or just need "continue", and finding out means clicking through tabs. Screen scraping and GUI automation are brittle. BAT already has a remote protocol for its own desktop and phone clients, so the connector reads that, and a supervising agent does the checking.

長時間執行的 coding agent 會做完、會卡在問題上、會撞到用量額度，有時只差一句「continue」，而你只能一個個分頁點進去看。抓畫面、模擬 GUI 操作都很脆弱。BAT 本來就有一套給自家桌面與手機客戶端用的遠端協定，連接器直接透過這套協定讀取，讓負責監督的 agent 替你去看。

Reading is always on. Anything that writes is opt-in per host, confirmed per call, rate-limited, and written to an audit log.
讀取預設開放；寫入要逐台授權、逐次確認，並有限速與稽核。
How it works運作方式

Read first. Opt in to act.

先讀，要動手再開啟。

Each host has its own switches in hosts.toml, and they stack: orchestrate needs writes, allow_all needs writes, and auto_cleanup needs orchestrate.

每台主機在 hosts.toml 裡有各自的開關，而且是一層疊一層：orchestrate 要先開 writes，allow_all 也要先開 writes，auto_cleanup 則要先開 orchestrate。

01

Import hosts from BAT

從 BAT 匯入主機

batc import-bat reads the BAT desktop client's profiles and writes hosts.toml with writes off: the wss:// URL, the pinned certificate fingerprint, and a token reference, never the token itself.

batc import-bat 讀取 BAT 桌面客戶端的 profile，寫出寫入功能關閉的 hosts.toml：wss:// 網址、固定的憑證指紋，以及 token 的參照，不會存 token 本身。

02

Connect an agent read-only

以唯讀接上 agent

Register the MCP server as "bat" in Claude Code, Codex, Cursor, Hermes, or any MCP client. Started read-only, it has only the 13 read tools, whatever the config says.

在 Claude Code、Codex、Cursor、Hermes 或任何 MCP 客戶端裡，把 MCP 伺服器註冊成「bat」。以唯讀模式啟動時，不管設定檔怎麼寫，都只會有 13 個唯讀工具。

03

Triage and wait

分類與等待

sessions_triage labels every session (quota exhausted, waiting on a permission or a question, working, done) with an evidence line. session_wait blocks until a turn ends or a question appears.

sessions_triage 替每個 session 標上狀態（額度用完、等權限或等回答、工作中、已完成），並附上判斷依據。session_wait 會一直等到回合結束或出現提問。

04

Opt in, host by host

逐台主機開啟

writes = true adds nudging, answering, and relaying. orchestrate = true adds worktree sessions, Codex failover, merges, and gated cleanup.

writes = true 會加上推動、回答與轉達；orchestrate = true 再加上 worktree session、轉給 Codex 接手、merge，以及有關卡把關的清理。

What you get你會得到什麼

Three tiers, and gates on anything that writes.

三層權限，寫入有關卡。

32 MCP tools and 32 batc subcommands. Only the read tier is on by default, and the tools of a disabled tier are never registered.

共 32 個 MCP 工具、32 個 batc 子指令。預設只開唯讀層；沒開啟的權限層，工具根本不會註冊。

01

Read tier, always on

唯讀層，永遠開啟

13 tools list hosts, workspaces, and sessions, read transcripts in pages, wait for a turn to end, and show worktree diffs. The turn marker returned by a send keeps an older reply from being reported as the new result.

13 個工具可以列出主機、工作區與 session，分頁讀取對話，等待回合結束，並顯示 worktree 的 diff。送出訊息時拿到的 turn marker，可以避免把上一輪的回覆誤當成新結果。

session_read · session_wait
02

Opt-in nudge tier

選擇性開啟的推動層

With writes = true, 7 tools send a message, say continue, interrupt, answer a question or permission prompt, switch permission mode, or relay a person's words verbatim. Every call needs confirm=true.

開啟 writes = true 後多 7 個工具：送訊息、說 continue、中斷、回答提問或權限請求、切換權限模式，或逐字轉達某個人的原話。每次呼叫都要帶 confirm=true。

writes = true
03

Separate fan-out tier

獨立的調度層

orchestrate = true, which needs writes, adds 12 tools: start sessions in fresh git worktrees, fan a bat-fanout plan out to parallel sessions, merge only clean, conflict-free branches, and remove worktrees. The default cap is 4 orchestrated sessions per host.

orchestrate = true（必須先開 writes）再加 12 個工具：在新的 git worktree 開 session、把 bat-fanout 計畫分派給平行的 session、只 merge 乾淨且沒有衝突的分支，以及移除 worktree。預設每台主機最多同時調度 4 個 session。

orchestrate = true
04

Quota failover to Codex

額度用完，轉給 Codex

Triage spots Claude sessions stopped by a usage quota from the limit text in the transcript. session_failover starts Codex in the same worktree and branch, with a handoff prompt that carries the original task, the latest instruction, recent output, and git state.

Triage 從對話裡的額度提示文字，找出因為用量額度停下來的 Claude session。session_failover 會在同一個 worktree、同一個分支開 Codex 接手，交接 prompt 帶著原始任務、最新指示、最近的輸出與 git 狀態。

session_failover
05

Gated auto-approve

有門檻的自動核准

approve_pending answers permission prompts, never questions, with "don't ask again", then raises the session to allow-all. It only runs on hosts whose default_permission_mode is allow_all, and it never switches a Claude session mid-turn.

approve_pending 只核准權限請求、不回答提問，核准時勾選「不再詢問」，再把 session 提升為 allow-all。它只在 default_permission_mode 設為 allow_all 的主機上執行，也絕不在 Claude 回合進行中切換權限。

approve_pending
06

Cleanup behind hard gates

有硬性關卡的清理

session_cleanup is a dry run by default, and acting needs auto_cleanup = true on the host. It merges only when the worktree is clean, the branch is ahead, a passing verification record matches the commit, risk checks pass, and Jev agrees at 0.8 or higher. Branches are always kept.

session_cleanup 預設只做 dry run，要真的動手，主機必須開啟 auto_cleanup = true。只有在 worktree 乾淨、分支領先、有對應同一個 commit 的通過驗證紀錄、風險檢查沒問題，而且 Jev 信心達 0.8 以上時，才會 merge。分支一律保留。

session_cleanup
Architecture系統架構

A client of BAT, not a part of it.

是 BAT 的客戶端，不是 BAT 的一部分。

The connector is one more remote client of a BAT host, next to BAT's own apps. Its checks live in the client core, below the MCP layer, so the CLI and every MCP client get the same rules.

連接器只是 BAT 主機的另一個遠端客戶端，和 BAT 自己的 app 並列。檢查都放在客戶端核心，位於 MCP 層之下，所以 CLI 與每個 MCP 客戶端套用的是同一套規則。

Read freely. Write on purpose.

放心讀，小心寫。

  • Unofficial: not affiliated with or endorsed by BAT's authors
  • 非官方：與 BAT 作者沒有關係，也未經其背書
  • A TLS pin mismatch aborts before the token is sent
  • 憑證指紋不符，就在送出 token 之前中止
  • Tokens come from env:, file:, or bat-profile: references and are redacted from errors
  • Token 只從 env:、file:、bat-profile: 參照讀取，錯誤訊息一律遮蔽
  • Never sends reset, kill, PTY writes, file operations, settings, or installs
  • 絕不送出 reset、kill、PTY 寫入、檔案操作、設定與安裝
  • No push, tag, or PR channel: merges stay in the host's main checkout
  • 沒有 push、tag 或 PR 通道：merge 只留在主機的主要 checkout
Design decisions設計取捨

Why it is shaped this way.

為什麼長這個樣子。

01

The protocol, not the screen

走協定，不抓畫面

BAT's own clients already use bat-remote/v2, so the connector does too: no screen scraping, no GUI automation. The cost is coupling to a protocol read from BAT's source (v3.2.12) that can change between releases.

BAT 自己的客戶端本來就用 bat-remote/v2，連接器也走同一套：不抓畫面、不模擬 GUI 操作。代價是綁在一套從 BAT 原始碼（v3.2.12）讀出來的協定上，而它可能隨版本改變。

02

Unregistered beats refused

不註冊，比拒絕更可靠

A tool that does not exist cannot be talked into running. Write and orchestrate tools are registered only when some host enables them, and even then each call needs confirm=true.

不存在的工具，就不可能被說服去執行。寫入與調度工具只有在某台主機開啟時才會註冊，就算註冊了，每次呼叫也都要帶 confirm=true。

03

Code decides first, a model last

先由程式判斷，模型最後才上場

Cleanup checks git state, a verification record for the exact commit, and risk rules in code before it asks Jev anything. If Jev is unavailable, a merge escalates instead of going through.

清理流程先用程式檢查 git 狀態、對應同一個 commit 的驗證紀錄與風險規則，最後才問 Jev。Jev 不在時，merge 一律升級給人處理，不會直接放行。

04

Branches are never deleted

分支永遠不刪

Cleanup removes worktree folders but keeps every branch, so a merge or removal can be undone from the branch. Failover reuses the same worktree instead of copying work around.

清理會移除 worktree 資料夾，但每個分支都保留，merge 或移除之後都還能從分支救回來。Failover 直接沿用同一個 worktree，不把工作搬來搬去。

Honest status誠實的現況

Where it stands.

目前的樣子。

Alpha, started in late September 2026 and changing daily. Every changelog entry is marked unreleased: no version tags, no GitHub releases, no PyPI package. BAT is by TonyQ; this project is not affiliated with or endorsed by BAT's authors, and a BAT update can break it.

Alpha 階段，2026 年 9 月下旬才開始寫，目前幾乎每天都在改。CHANGELOG 每一版都標著 unreleased：沒有版本 tag、沒有 GitHub release，也沒有 PyPI 套件。BAT 的作者是 TonyQ；本專案與 BAT 作者沒有關係、未經其背書，BAT 一更新就可能讓它失效。

Works today

目前可用

  • Read tier: 13 MCP tools, plus the batc CLI with batc --json for scripts
  • 唯讀層：13 個 MCP 工具，加上 batc CLI，腳本可用 batc --json
  • Per-host write and orchestrate tiers with confirm=true, rate limits (by default one write per session per minute, 30 per hour), and an append-only audit log
  • 逐台主機開啟的寫入層與調度層：每次呼叫要 confirm=true，有速率限制（預設同一 session 每分鐘一次、每小時總共 30 次），並寫入只能附加的稽核紀錄
  • Triage from transcript patterns and BAT-STATUS markers, and quota failover to Codex in the same worktree
  • 依對話內容規則與 BAT-STATUS 標記分類 session，額度用完時在同一個 worktree 轉給 Codex 接手
  • approve_pending and gated session_cleanup; cleanup never deletes a branch
  • approve_pending 與有關卡把關的 session_cleanup；清理絕不刪除分支
  • A pytest suite against a mock TLS BAT server: 278 passed, 33 skipped in a local run on 2026-09-30
  • 以模擬的 TLS BAT 伺服器測試的 pytest 套件：2026-09-30 本機執行，278 個通過、33 個略過

Limits and not yet

限制與尚未完成

  • The protocol was read from BAT's source (v3.2.12) and can change between BAT releases
  • 協定是從 BAT 原始碼（v3.2.12）讀出來的，BAT 改版時可能跟著變
  • Linux and macOS only (it uses fcntl file locks)
  • 只支援 Linux 與 macOS（用到 fcntl 檔案鎖）
  • Automatic merges need the optional Jev layer (a TypeSafe or OpenRouter key). Without it, cleanup keeps, cleans, or escalates, but never merges
  • 自動 merge 需要選用的 Jev 判斷層（TypeSafe 或 OpenRouter 的 key）。沒有它，清理只會保留、清掉或升級給人處理，不會 merge
  • BAT's Codex sessions do not echo message IDs, so Codex turn tracking falls back to timestamps and Codex sends are not retried after a disconnect
  • BAT 的 Codex session 不會回傳訊息 ID，所以 Codex 的回合追蹤只能改用時間戳，斷線後也不會自動重送
  • The task service (batc serve and the work_* tools) is experimental: its Goose planner is off by default, so submitted tasks stay queued
  • 任務服務（batc serve 與 work_* 工具）還在實驗階段：Goose 規劃器預設關閉，送出的任務會一直排隊
