## 開發方式與注意事項

- **測試與 lint**：`uv run ruff check .`、`uv run pytest -q`（約 3 分鐘）。只改一個模組時先跑對應的 `tests/test_*.py`。
- **Dashboard 驗證**：用 Playwright 對 MockBat 加真的 git 跑，`tests/test_checkpoints.py` 的 `LocalRunner`、`RealGitLog` 可以當主機。
  - 依專案的 Playwright 設定安裝瀏覽器；不要依賴維護者機器上的快取路徑或全域套件。
  - 本輪的 harness 放在 session 暫存區，沒有進 repo，需要時照 `tests/test_work_items.py` 的 fixture 重建。
  - 每次都檢查 zh-TW、en、390 px 寬，以及畫面上沒有 `null`／`undefined`／`[object …]` 文字。
- **Dashboard 的幾個規則**：
  - CSP 不允許 inline style 屬性，縮排用 `el.style.setProperty`。
  - `replaceChildren` 會把 `null` 印成文字，要經 `fill()`。
  - 語法檢查要把 `app.js` 複製成 `.mjs` 再 `node --check`（直接檢查抓不到重複宣告）。
  - 即時更新不會在打開的編輯欄或有焦點的輸入框底下重畫。
- **管理資料的修改**都經 OperationService，帶上讀到的版本、指紋、順序或固定狀態；變更和 `management_applied` 在同一個交易裡寫入。
- **流程**：每個 PR 用多 agent 的對抗式審查（四個面向加獨立反駁者）。Codex 也會在開 PR 時自動審。
  - 工作流程的 worktree isolation 需要目前目錄是 git repo，不是的話 agent 建 worktree 會失敗。
  - `.claude/worktrees` 是工作流程的暫存，不在 `.gitignore` 裡；每個 clone 要自己加到 `.git/info/exclude`，不要 commit。
- **不要用 `pkill -f`**：會連自己的 shell 一起殺掉。背景程序要記下 PID 再 `kill`。
- **疊在一起的 PR 要由下往上合併**：用 merge commit，合併下一個之前先把它的 base 改成 `main`。
