## 這一輪的分工

- 實作與獨立審查分工；整合者核對每個包的文件、測試與契約，再處理發布及合併。

  - README（en、zh-TW）、CHANGELOG 與測試。
- 每一輪的流程：
  1. **寫 brief**：要保證的結果、測試與包裝。固定要求：
     - 依序跑完整的 `uv run pytest -q` 與 Python 3.10 全套；
     - 不得全域 monkeypatch `pathlib.Path` 或其他 stdlib class；
     - 不得 push；
     - 用共同格式回報。
  2. **審 worker 的 commit**：對照 brief、spec 與計畫，自己讀程式碼。
  3. **通過才 push**：
     - 先用 `git ls-remote` 確認遠端 head，再用 `merge-base --is-ancestor` 確認是快轉；
     - 掃新增行有沒有 IP、email 或金鑰；
     - 用 `git push --force-with-lease=refs/heads/<分支>:<舊 head>` 推上去。
  4. **跟 Codex 往返**：在它的 thread 回覆修法，更新 PR 說明，留言 `@codex review`，等 CI 與 Codex。
  5. **查證新意見**：Codex 的新意見先對照程式碼查證，成立才派下一輪，不成立就在 thread 說明。
- CONFLICTING 的 PR 沒有 CI，push 前要在 worker 的 clone 自己跑一次完整測試。

### #35 的 root walk 修正（`4e80b47`，已審、已 push）

問題是我審查時找到的，不是 Codex 提的：
- 問題：`registry_worktree_root()` 對沒有共用 worktree 的 failover successor 也沿 `failover_of` 往上走，把舊 worktree 的身分綁給它。另外，`shared_worktree_from` 從來沒有程式寫入。
- 修法：只在真的共用 worktree 時往上走，`registry_bindings()` 的 fallback 也用同一個 parent rule。`shared_worktree_from` 已移除；`shares_worktree_with` 是 `bcf9745`（0.2.0）加入的。沒有記錄 worktree 的 session 一律拒絕 BAT worktree 動作，比修正前更嚴。
- 留給 rebase 輪：policy 的 `classify()` 沒有傳 `lead_of`。缺 `lead_session_id` 的舊 reviewer 列，在身分與 policy 兩邊可能判出不同的 root。目前的程式寫 reviewer 列時都會帶 `lead_session_id`，所以只影響舊資料。

### #36 的兩個新 P1（已查證，`opsunify p2apause` 在修）

兩項都已在 thread 回覆，brief 是 `briefs/opsunify.p2a-pause-authority.prompt.md`，每項一個 commit。

1. **4223125524**（`task_bat.py:872`），確定是 bug：
   - 現象：verifier 子程序執行中有人 `task.pause`，最後那次受保護的寫入會丟 `TaskControlRefused`。`_tick_task` 的通用例外處理把它當成 verifier 失敗，暫停中的 task 就從 `verifying` 變成 `needs_ted`，之後 resume 也不會重跑驗證。
   - 修法：視為取消。保留原狀態與暫停，不記 evidence；resume 後的下一個 tick 從頭重跑驗證。spec 要列出 tick 能走到的每個受保護路徑。
2. **4223125515**（`lifecycle.py:473`），屬於加固：
   - 查證結果：MCP、CLI、HTTP 都不會傳 `task_id`。唯一會傳的是 coordinator（`task_bat.py:684`），而且帶齊所有 callback，所以外部入口目前碰不到。
   - 問題：擁有權檢查把公開的 `task_id` 當成授權。程式內部只要帶上它，就能不經 coordinator 啟動 successor。
   - 修法：改成只有 coordinator 的 failover 路徑能建立的內部 authority 物件。單獨的 `task_id` 只當身分資料。

## 開發方式與注意事項（這輪新增）

- 開發工作使用隔離 checkout，先核對來源與分支；私人計畫、派工紀錄及本機 logs 不納入公開文件。
- Review 應固定完整 commit，記錄範圍與 findings；額度提示不算審查通過。
- **測試**：
  - 判斷 operation 狀態前，用 `tests/operation_helpers.settle_operations`，不要靠 `ops.drain()` 的 deadline。高負載下曾因此 flaky。
  - 多套測試要依序跑，不要同時跑。
- **push 前的掃描**只看新增行。已知的誤報：`@pytest`、`127.0.0.1`、`sk_continuation`，以及 `task_…` 被 `sk_` 規則抓到。
- **不變的安全規則**：
  - 不 commit 真實主機名、IP、指紋、token、session ID、workspace 名稱或 email；
  - Hermes、Grokbot 的 token 不給 `approve`，也不給 `cleanup_discard`；
  - manual 與 unknown 資源永遠唯讀；
  - 不加繞過 API，也不加操作者 release 指令；
  - Delivery part B 不放正式 recipe 值，只用保留的範例網域。
