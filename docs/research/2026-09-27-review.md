### Part 1 (review of bat-agent-connector vs Goose)
Reviewed snapshots: better-agent-terminal 5a61d43 (Sep 24 2026), bat-agent-connector e72e5e4 (v0.2.4, Sep 27 2026), goose 04ed836 (Sep 25 2026). Static review only.

Recommendation: keep bat-agent-connector as the foundation; add stock Goose later as an optional execution engine via ACP (Goose accepts `args.mcp_servers` in ACP session setup, so the connector stays MCP; `goose acp` subprocess or `goose serve`). Don't route status lookups/permission checks/budget/known-turn waits through Goose; only interpretive work. Goose needs its own model provider. Preserve relay.py's design (keep human's original request, label relay interpretation separately, coding session produces the fan-out plan).

Existing modules: client.py (WS, cert pinning before auth token, request correlation, bounded subscriber queues), service.py, orchestrate.py (session/worktree create, merge/remove checks), lifecycle.py (Claude-to-Codex failover, cleanup, relay/fan-out), registry.py (fcntl.flock + atomic replace), jev.py (TypeSafe), mcp_server.py / cli.py (`batc`).

Finding 1 (high): `session_send()` sends `clientMessageId` like `batc-<uuid>`; BAT Claude `emitUserEcho()` uses it as the echoed message `id`; connector returns `turn_marker = m.get("id") or str(ms)`; but `marker_ms()` only parses numeric timestamps, ids ending in numeric timestamp, or ISO timestamps, so `session_wait(after=sent["turn_marker"])` can fail. tests/test_turn_marker.py expects mock markers starting `user-`, masking this. Workaround: when `marker_source == "sent_message"` and `after_ms` present, pass that. Proper fix: find echo by exact clientMessageId (not first 160 normalized chars of prompt), explicit cursor contract. `_progress_after()` treats newer non-user messages as progress; with queued sends old-turn output can arrive after the new echo; need command-to-turn correlation with accepted/running/terminal states.

Finding 2 (high): `_write_lock()` is an asyncio.Lock per event loop; unrelated sessions in one loop share it; doesn't coordinate other processes/VMs/BAT GUI. isStreaming check is racy vs GUI. Recommend one coordinator with per host/session or worktree ownership and control-version; true enforcement needs BAT host-side gate.

Finding 3 (high): `_failover_one()` checks for an existing successor before `_write_lock()`; `registry.reserve()` checks cap and supersedes but doesn't enforce unique active successor per `failover_of`; two controllers can create two Codex successors on the same worktree. Fix: atomic reserve-unique-successor transaction. Old Claude session remains until cleanup; establish handoff before successor writes.

Finding 4 (medium/high): `append_workspace_terminal()` load/append/reload-check/save/verify has an acknowledged lost-update race with GUI saves. Fix needs host-side atomic append or revision-checked update (proposed `workspace:add-terminal`, doesn't exist). Keep tab registration opt-in.

Finding 5 (high): cleanup has good checks (states, dirty files, branch, main checkout, shared worktrees, sensitive changes) but `test_evidence()` pattern-matches tool commands and textual status, not bound to candidate commit/tree; gate can proceed without test evidence if Jev `tests_ok` is high; `BAT-STATUS: MILESTONE` raises completion score. Separate TURN_FINISHED / AGENT_CLAIMS_COMPLETE / VERIFIED_CANDIDATE / APPROVED_FOR_MERGE; verification record = commit/tree hash, command, exit code, environment, log ref; code change invalidates. Jev for triage, not execution evidence.

Goose: ACP code persists sessions, resolves providers, `ActiveRunRegistry` rejects concurrent prompt runs per Goose session, but doesn't protect external BAT sessions. `AcpProvider::resume()` exists in source (docs say unsupported); verify per deployment.

Proposed structure: `control/{tasks,commands,ownership,events,verification}.py`, `engines/{direct_bat,goose_acp}.py`, `api/{task_mcp,dashboard_api}.py`. One authoritative coordinator with transactional local DB; persist command intent with idempotency key before dispatch; reconcile after timeout. BAT owns coding sessions, Goose its agent session, service owns business task + mappings. Goose gets only task-scoped tools, not `task_submit` (no recursion). Keep HTTP loopback-only; network dashboard needs real authn/z (MCP actor currently recorded as "mcp"). Dashboard: tasks, milestones, ownership, blockers, failover links, worktrees, verification; leave conversations in BAT.

Stages: 1 correctness (marker, atomic failover, merge verification); 2 shared service + read-only dashboard + CLI on same service; 3 Goose via ACP with task-scoped MCP; 4 safe takeover (BAT host enforcement or separated automation sessions); 5 compare direct vs Goose on same tasks. Test: real UUID echoes, old-turn events after queued send, two simultaneous failovers, GUI save racing tab registration, disconnect after command acceptance, code change after successful test.

### Part 2 (Buzz, block/buzz @ b0d6fb8, Sep 26 2026)
Buzz is a human+agent shared workspace (channels, Git events, workflows, search, signed activity; relay is source of truth; desktop app, CLI, ACP harness that spawns agent subprocesses; a different ownership model from controlling existing BAT sessions). Full self-host = Postgres, Redis, MinIO, Git volume, relay, optional Caddy. Don't adopt the full platform now; only if it replaces Discord/planned dashboard.

Worth studying: `buzz-acp run --task ./task.json`: one fresh agent process + ACP session, structured terminal record, exits; no relay subscriptions. Trusted launch config (executable, credentials, tool permissions, working dir) is outside the task prompt. Explicit outcomes: completed/cancelled/deadline/failed; cooperative cancel then adapter shutdown; completed turn can carry reasons max_tokens/refusal; exit 0 is not proof of success. But `taskId` is correlation not dedup key (can execute twice); no persistent ledger or HTTP queue; creates fresh sessions; depends on other Buzz crates. Read `crates/buzz-acp/src/run_task.rs` + `isolated_execution.rs`.

Borrow: bounded execution contract (trusted config = capabilities; task input = work; runner enforces time/cancel; separate verifier decides acceptance). Deterministic control commands (stop/takeover/cancel handled by code before any prompt; owner-only author gate). Shared activity record that dashboard, CLI, Hermes all reference instead of reconstructing. Keep attribution separate from verification.
